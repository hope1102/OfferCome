# OfferCome

OfferCome 是一款本地优先的 Edge / Chrome 网申简历自动填写扩展。它可以把结构化简历资料保存在浏览器本机，识别招聘网站中的表单字段，并通过“一键填写”或“定点填写”将资料写入网页。

扩展不会自动点击提交按钮，也不会把简历和网页内容上传到服务器。最终检查与投递始终由用户完成。

当前版本：`0.4.0`

## 主要功能

### 常驻浏览器侧栏

- 点击工具栏中的 OfferCome 图标后，在浏览器右侧打开侧栏。
- 点击网页、切换输入框时侧栏不会因为失去焦点而关闭。
- 侧栏会持续显示当前页面的扫描结果、填写入口和当前定点填写目标。
- 只有主动点击侧栏关闭按钮时才会关闭。

### 一键填写

- 扫描当前网页中的可编辑表单控件。
- 综合 `label`、`placeholder`、`name`、ARIA 属性、字段标题和附近上下文判断字段含义。
- 支持普通输入框、文本域、原生下拉框、单选框、复选框、日期控件和 `contenteditable`。
- 兼容 React / Vue 等框架常见的受控输入事件。
- 针对北森 / iTalent 风格表单增强了分层标题、自定义下拉框和“国家区号 + 手机号”复合控件识别。
- 填写完成后显示成功、跳过、失败和未匹配统计。

### 定点填写

适合自动匹配不准确、字段名称特殊，或只想填写某一个输入框的情况。

1. 先点击招聘网页中需要填写的输入框。
2. 在 OfferCome 侧栏的“定点填写”区域选择资料。
3. 选中的资料只会写入刚才点击的那个输入框。

定点填写区域提供模块导航，可以选择：

- 基本信息
- 求职期望
- 教育背景
- 实习 / 工作经历
- 项目经验
- 校园经历
- 家庭成员
- 获奖经历
- 专业技能
- 语言能力
- 证书信息
- 论文 / 专利
- 自我介绍
- 常见问答

导航只展示当前简历中已有内容的模块，并显示可用字段数量。选择模块后仍可使用搜索框继续查找学校、专业、课程、公司、项目等具体资料。

### 简历资料管理

可以结构化维护以下资料：

- 基本信息和联系方式
- 求职期望
- 教育经历
- 实习与工作经历
- 项目经历
- 校园与学生干部经历
- 家庭成员
- 专业技能与语言能力
- 证书和获奖经历
- 论文与专利
- 自我介绍
- 常见网申问答

资料支持 JSON 导入、导出和本地备份。请勿把包含真实个人信息的导出文件提交到公开仓库。

### 求职工作台

- 一键填写后自动生成本地申请记录，默认状态为“已填写”，不会误记为“已投递”。
- 看板支持拖拽更新申请阶段。
- 支持状态时间线、备注、下一步日期、投递复盘和归档。
- 申请记录可以导出为 JSON。

### 安全与保守匹配

- 默认不覆盖网页中已有内容。
- 默认不填写敏感字段。
- 从不自动点击提交、投递或确认按钮。
- 忽略密码框、禁用字段和只读字段。
- 多个候选项含义接近、章节冲突或置信度不足时会跳过，不会强行猜测。
- 页面包含的经历数量多于简历资料时，不会重复使用最后一条资料补齐。
- 写入后会重新读取控件；被页面拒绝或回滚的值会计为失败。

## 安装方法

OfferCome 目前采用“加载解压缩扩展”的方式安装，无需构建。

### Microsoft Edge

1. 下载或克隆本仓库。
2. 在 Edge 地址栏打开 `edge://extensions`。
3. 开启“开发人员模式”。
4. 点击“加载解压缩的扩展”。
5. 选择本仓库根目录，也就是包含 `manifest.json` 的 `OfferCome` 文件夹。
6. 将 OfferCome 固定到浏览器工具栏。

### Google Chrome

1. 在 Chrome 地址栏打开 `chrome://extensions`。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择包含 `manifest.json` 的 `OfferCome` 文件夹。

扩展使用 Manifest V3 和 Side Panel API，需要 Chromium 114 或更高版本。

## 使用方法

### 第一次使用

1. 点击浏览器工具栏中的 OfferCome 图标，打开常驻侧栏。
2. 点击侧栏底部的“编辑简历资料与导入导出”。
3. 填写简历资料，或者导入以前导出的 JSON 文件。
4. 点击“保存全部资料”。

### 一键填写网申表单

1. 打开招聘网站的网申页面。
2. 点击 OfferCome 图标打开侧栏。
3. 点击“扫描页面”。
4. 查看已匹配、高置信和必填待处理数量。
5. 点击“一键填写”。
6. 人工检查所有字段，补充附件、验证码和未识别项目。
7. 确认无误后，由你自己点击网站的提交按钮。

默认情况下，OfferCome 会保留页面中已经存在的内容。如果需要替换已有值，请先勾选“覆盖页面已有内容”。

### 定点填写单个字段

1. 保持 OfferCome 侧栏打开。
2. 点击网页中需要填写的输入框，例如“专业课程”。
3. 确认侧栏显示“当前目标：专业课程”。
4. 点击导航，选择“教育背景”。
5. 点击“主修课程”，内容会写入当前目标输入框。

如果目标输入框已有内容，需要先勾选“覆盖页面已有内容”。每次定点填写只处理最后一次在网页中选中的控件。

### 管理投递进度

1. 在侧栏底部点击“打开求职工作台”。
2. 将真正提交过的申请从“已填写”移动到“已投递”。
3. 根据实际进度更新为笔试、面试、Offer 或其他阶段。
4. 记录下一步日期、备注和复盘内容。

## 浏览器权限说明

| 权限 | 用途 |
| --- | --- |
| `storage` | 在浏览器本机保存简历、设置和申请记录 |
| `activeTab` | 响应用户操作，获取当前活动标签页 |
| `scripting` | 在必要时检查当前页面是否可由扩展访问 |
| `sidePanel` | 提供不会因点击网页而关闭的常驻侧栏 |
| `<all_urls>` | 在不同公司和招聘平台的网申域名中识别表单 |

`<all_urls>` 用于兼容不同招聘网站。OfferCome 不会收集浏览历史，也不会将页面内容发送到远程服务。

## 常见问题

### 提示“Cannot access contents of the page”

通常是扩展刚重新加载但当前网页还没有刷新，或者浏览器没有授予该网站访问权限。

1. 打开 `edge://extensions` 或 `chrome://extensions`。
2. 找到 OfferCome 并点击“重新加载”。
3. 回到招聘网页并刷新页面。
4. 在扩展详情中确认“网站访问权限”允许当前网站或所有网站。
5. 再次点击网页输入框，然后使用定点填写。

浏览器内部页面、扩展商店、部分新标签页和受保护页面禁止扩展注入脚本，因此无法填写。

### 点击网页后侧栏消失

请确认已经重新加载 `0.4.0` 或更新版本。新版使用浏览器原生侧栏，不再使用点击外部就关闭的工具栏弹窗。

### 定点填写提示没有找到目标

- 先点击网页中真正可编辑的输入框，再点击侧栏资料。
- 如果网页刷新、切换步骤或重新渲染了表单，需要重新点击目标输入框。
- 某些自定义组件的可见外壳并不是实际输入控件，可以尝试点击文字输入区域。
- 刷新网页后要重新选择目标。

### 字段没有自动填写

- 点击“扫描页面”重新识别。
- 检查简历资料中是否存在对应内容。
- 使用定点填写作为补充。
- 文件上传、图片验证码、短信验证码和复杂级联选择通常需要手动处理。

### 修改代码后没有生效

1. 在扩展管理页面点击 OfferCome 的“重新加载”。
2. 刷新目标招聘网页。
3. 关闭旧侧栏并重新打开。

## 数据与隐私

- 简历资料保存在 `chrome.storage.local` 对应的浏览器本地存储中。
- 项目没有后端服务，核心填写流程不需要账号。
- 卸载扩展或清除扩展数据可能删除本地资料，建议定期导出 JSON 备份。
- 导出的 JSON 可能包含手机号、证件信息等敏感内容，请妥善保管。
- 在公共电脑上使用后，应删除扩展资料并卸载扩展。

## 项目结构

```text
OfferCome/
├─ manifest.json              扩展清单与权限
├─ src/
│  ├─ background/             初始化和侧栏行为
│  ├─ content/                页面扫描、字段匹配与填写
│  ├─ options/                简历资料编辑和导入导出
│  ├─ popup/                  常驻侧栏界面（保留早期目录名）
│  ├─ shared/                 数据模型、字段字典和公共工具
│  └─ tracker/                本地求职工作台
├─ tests/
│  ├─ core.test.js            无依赖核心测试
│  └─ fixtures/               脱敏浏览器回归页面
└─ REQUIREMENTS.md            产品范围、约束和长期路线
```

## 本地开发

项目使用原生 HTML、CSS 和 JavaScript，没有打包步骤，也不要求安装 npm 依赖。

修改代码后：

1. 在扩展管理页面点击“重新加载”。
2. 刷新测试网页或目标招聘网页。
3. 重新打开侧栏进行验证。

运行核心测试：

```powershell
node tests/core.test.js
```

检查 JavaScript 语法：

```powershell
Get-ChildItem src -Recurse -Filter *.js | ForEach-Object { node --check $_.FullName }
```

`tests/fixtures/` 中的脱敏页面用于回归测试：

- `generic-application.html`：通用 DOM 填写、章节隔离和重复经历边界。
- `beisen-application.html`：北森式标题、自定义下拉和复合手机号。
- `content-script-integration.html`：一键填写到申请记录去重的完整流程。
- `options-editor-preview.html`：简历资料编辑与本地存储。
- `tracker-preview.html`：工作台看板和投递复盘交互。

## 已知边界

- 无法绕过浏览器禁止扩展访问的受保护页面。
- 跨域 iframe、验证码、文件上传和部分高度定制的组件可能需要手动操作。
- 自动匹配是辅助功能，不能替代投递前的人工检查。
- 招聘网站更新页面结构后，可能需要调整站点适配规则。

详细产品要求和后续路线见 [REQUIREMENTS.md](./REQUIREMENTS.md)。
